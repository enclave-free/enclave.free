# Native Tool Calling with One Tool Round

Status: Superseded in its one-batch constraint by [ADR-0030](0030-bounded-native-tool-loop.md). The remaining native-protocol, trust-boundary, and hard-cut decisions are still accepted.

Sage will expose enabled **Tool** contracts through the configured **Model Provider**'s native Tool-calling protocol instead of using a separate DSRs typed planner. A **Conversation** allows one model-selected Tool batch: the model may answer directly, or Sage executes the selected Tools once and returns their successful, failed, or guarded results for the final answer. One generic retry may repair an unusable native Tool-call response, but deterministic intent rules must not force or reject an otherwise valid model-selected plan. Final model prose streams without content-specific quarantine, completeness policing, or answer rewriting; Sage deterministically enforces only protocol validity and existing credential and secret boundaries. This supersedes ADR-0023's rejection of provider-native Tool calling and ADR-0027's separate typed planning phase because the authoritative GLM 5.2 Conversation model was verified to support native Tool calls, and the native path removes the `replan_after_results` contract, the Tool-planning parser, content-specific plan correction, prose scanners, and the extra planning request on no-Tool turns.

## Consequences

Every configured Conversation model must support the native Tool-calling contract. Sage continues to own Tool availability, authorization, execution, result handling, Activity, and Conversation Trace; the **Model Provider** selects Tools but never executes Enclave Tools itself. A final response must contain usable answer content and a supported provider completion reason, and a second Tool batch is not executed. Temporary Tool transport failures remain the responsibility of Tool-level retry policy, while a later Conversation turn is the retry boundary for a completed Tool batch.

The native boundary accepts at most eight calls in the batch, requires unique provider call identifiers, gives every Tool attempt a finite timeout, and preserves the existing 4,000-character per-result and 12,000-character batch context budgets. Provider events may establish first-event timing, but hidden provider reasoning is not copied into Activity, Conversation Trace, or operational logs.

List-style Tools return their best-ranked first page together with structured availability metadata such as returned count, total count, and whether more results exist. The model receives that metadata so it can describe the result honestly or offer additional options naturally. Sage does not automatically fetch another page, require completeness language, or expose Tool and pagination mechanics to the user.

Search quality remains the responsibility of each Tool. The Resource Directory may deterministically rank exact organization names, email addresses, phone details, and partial matches because those are generic properties of its search domain. Sage does not infer contact intent, force the Curated Resources Tool, or retry a completed lookup through contact-specific orchestration.

Tool descriptions remain short capability contracts rather than workflow prompts. Knowledge Search states that uploaded documents may use different languages or titles and that multiple queries may be useful. Curated Resources states that it searches curated services and contact information and returns relevance-ranked results with availability metadata. The descriptions do not prescribe conclusions, encode customer-specific vocabulary, or force a scripted search sequence.

Tool execution may retry once only when the call is safe to retry and failed through a clearly transient infrastructure condition, such as a connection failure, timeout, or retryable server response. Read-only calls are eligible; state-changing calls require an established idempotency guarantee and otherwise are not retried automatically. Empty results, weak relevance, rejected arguments, and other semantic outcomes are final Tool results rather than retry signals. After the retry boundary is exhausted, the model receives the actual success, failure, or guarded result and answers naturally.

The transition is a hard cut. The separate typed Tool planner, planner fallback flag, contact-specific intent rules, plan validators and sanitizers, post-Tool replanning, and final-answer quarantine are removed rather than retained as an alternate execution path. Provider configuration rejects Conversation models that do not support the native Tool-calling contract.
