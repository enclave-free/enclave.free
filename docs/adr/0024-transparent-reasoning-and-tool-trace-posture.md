# Transparent Reasoning and Tool Trace Posture

Status: Still authoritative for live and persisted operational trace data. [ADR-0034](0034-audience-aware-conversation-activity.md) supersedes its identical Admin/User presentation posture, and [ADR-0029](0029-native-tool-calling-with-one-tool-round.md) supersedes its raw provider-reasoning posture: the native Conversation round publishes content-free model lifecycle, Tool selection and outcomes, retries, Retrieval details, measurable timing, and aggregate Model Usage Observations, but not hidden provider reasoning.

The Enclave Free Prototype retains live and persisted Conversation Traces transparently during the prototype phase. One guarded trace shape carries model request boundaries, content-free Tool-selection observations, Tool attempts and terminal outcomes, retries, Retrieval details, and timing for both Admin Conversations and User Conversations. As decided in ADR-0034, Admin Activity presents that operational detail while User Activity presents product-meaningful work without those diagnostic rows. This supersedes the earlier sanitized-only trace-data posture in ADR-0013 while retaining one guarded trace contract for both actor types.

Conversation Streaming Transport emits append-only `trace_delta` events from inside Sage's native Tool round as work happens. Streaming clients retain those deltas and derive audience-appropriate assistant-ui-style Activity and Tool-call message parts at render time, while non-streaming clients receive the accumulated Conversation Trace in the final response. Conversation Traces persist with the assistant turn, appear after refresh, and are included in conversation exports by default.

The shared Conversation UI Surface keeps Activity available for both actor kinds. User Activity starts collapsed, while Admin Activity may start expanded; audience and initial expansion are separate inputs. Each assistant turn may collapse its complete Activity body behind the Activity header. Optional reasoning summaries, Tool input/output summaries, and Retrieval summaries remain a second progressive-disclosure layer inside the expanded body. Collapsing or filtering presentation does not suppress streaming, persistence, export, or the shared Admin/User trace contract, and the UI must distinguish the whole-Activity control from the optional-detail control. The audience presentation is fixed by the surface: it is neither an Audit policy nor a configurable trace-visibility policy in Agent Settings.

Provider reasoning is not product trace material. When a Model Provider supplies opaque Provider Continuity State that belongs to an assistant Tool-call message, Sage may preserve it unchanged in memory for the current Bounded Native Tool Loop and return it only to the same model. Sage does not interpret, stream, log, persist, export, or carry that state into a later Conversation turn, and it does not ask the model to narrate hidden thoughts after the fact. Conversation Trace relies on the observable model, Tool, retry, Retrieval, timing, and aggregate usage lifecycle instead.

Each model request may ask the Model Provider to return aggregate input and output usage. When supplied, those counts become a sanitized Model Usage Observation attached to the existing per-request timing trace. They follow the associated Conversation Trace retention and deletion lifecycle, remain outside normal answer content, and never include prompts, answers, Tool arguments or results, or Provider Continuity State. Missing optional usage fields remain absent rather than being inferred, and these observations are diagnostic metadata rather than a new billing or analytics subsystem.

This transparent posture still keeps a minimal hard blocklist: credentials, private keys, internal auth headers, hidden system/developer instructions, raw secret reveal results, infrastructure/runtime environment dumps, and other authority-bearing internals must not be exposed. When the blocklist catches protected content inside a Trace Delta, Sage should keep the event, replace protected content with `[redacted]`, and mark it guarded by setting the Trace Delta `status` field to `guarded`. Operationally, a guarded event should look like `{ "kind": "tool_result", "status": "guarded", "content": "[redacted]" }`; there is no separate guarded boolean in the current Trace Delta contract. Hidden system/developer instructions and other authority-bearing internals should be redacted as whole content fields. Raw database rows may appear only when they were intentionally returned through an authorized product view or authorized Tool result. Trace generation remains Conversation metadata, not Audit Log evidence or product authority.
