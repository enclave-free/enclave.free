# Transparent Reasoning and Tool Trace Posture

The Enclave Free Prototype will expose live and persisted Conversation Traces transparently during the prototype phase: raw provider reasoning when available, model step boundaries, tool calls, tool results, retries, corrections, retrieval details, and timing should be visible in both Admin Conversations and User Conversations. This supersedes the earlier sanitized-only trace posture in ADR-0013 because the current product goal is to make Sage's agent loop highly auditable and to reduce perceived latency through immediate feedback, while keeping the implementation simple and avoiding actor-specific trace visibility plumbing.

Conversation Streaming Transport should emit append-only `trace_delta` events from inside Sage's Model-Driven Tool Loop as work happens. Streaming clients should render those deltas as assistant-ui-style reasoning and tool-call message parts, while non-streaming clients should receive the accumulated Conversation Trace in the final response. Conversation Traces should persist with the assistant turn, appear after refresh, and be included in conversation exports by default.

Raw reasoning is provider-contingent. If a Model Provider exposes reasoning content, Sage should stream and persist it as Reasoning Trace material. If a Model Provider does not expose reasoning content, Sage should not fabricate a raw Reasoning Trace by asking the model to narrate hidden thoughts after the fact. In that case, Conversation Trace should still expose model step boundaries, tool calls, tool results, retries, corrections, retrieval details, timing, and any explicit Reasoning Summary as a separate summary artifact.

This transparent posture still keeps a minimal hard blocklist: credentials, private keys, internal auth headers, hidden system/developer instructions, raw secret reveal results, infrastructure/runtime environment dumps, and other authority-bearing internals must not be exposed. When the blocklist catches protected content inside a Trace Delta, Sage should keep the event, replace protected content with `[redacted]`, and mark it guarded by setting the Trace Delta `status` field to `guarded`. Operationally, a guarded event should look like `{ "kind": "tool_result", "status": "guarded", "content": "[redacted]" }`; there is no separate guarded boolean in the current Trace Delta contract. Hidden system/developer instructions and other authority-bearing internals should be redacted as whole content fields. Raw database rows may appear only when they were intentionally returned through an authorized product view or authorized Tool result. Trace generation remains Conversation metadata, not Audit Log evidence or product authority.
