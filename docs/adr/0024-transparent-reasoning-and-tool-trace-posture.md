# Transparent Reasoning and Tool Trace Posture

Status: Still authoritative for live and persisted operational trace visibility. [ADR-0029](0029-native-tool-calling-with-one-tool-round.md) supersedes its raw provider-reasoning posture: the native Conversation round publishes content-free model lifecycle, Tool selection and outcomes, retries, Retrieval details, and measurable timing, but not hidden provider reasoning.

The Enclave Free Prototype exposes live and persisted Conversation Traces transparently during the prototype phase. Model request boundaries, content-free Tool-selection observations, Tool attempts and terminal outcomes, retries, Retrieval details, and timing are visible in both Admin Conversations and User Conversations. This supersedes the earlier sanitized-only trace posture in ADR-0013 while retaining one guarded trace shape for both actor types.

Conversation Streaming Transport emits append-only `trace_delta` events from inside Sage's native Tool round as work happens. Streaming clients render those deltas as assistant-ui-style Activity and Tool-call message parts, while non-streaming clients receive the accumulated Conversation Trace in the final response. Conversation Traces persist with the assistant turn, appear after refresh, and are included in conversation exports by default.

Provider reasoning is not product trace material. Sage may observe a content-free first provider event for latency measurement, but it discards hidden reasoning content and does not ask the model to narrate hidden thoughts after the fact. Conversation Trace relies on the observable model, Tool, retry, Retrieval, and timing lifecycle instead.

This transparent posture still keeps a minimal hard blocklist: credentials, private keys, internal auth headers, hidden system/developer instructions, raw secret reveal results, infrastructure/runtime environment dumps, and other authority-bearing internals must not be exposed. When the blocklist catches protected content inside a Trace Delta, Sage should keep the event, replace protected content with `[redacted]`, and mark it guarded by setting the Trace Delta `status` field to `guarded`. Operationally, a guarded event should look like `{ "kind": "tool_result", "status": "guarded", "content": "[redacted]" }`; there is no separate guarded boolean in the current Trace Delta contract. Hidden system/developer instructions and other authority-bearing internals should be redacted as whole content fields. Raw database rows may appear only when they were intentionally returned through an authorized product view or authorized Tool result. Trace generation remains Conversation metadata, not Audit Log evidence or product authority.
